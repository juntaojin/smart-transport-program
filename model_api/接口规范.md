# 智慧交通系统 — 模型 API 函数接口规范

---

## 目录结构约定

模型同学的所有代码、模型权重、配置文件**必须全部放在** `program/model_api/` 目录下：

```
program/
├── model_api/                  ← 模型同学的工作目录（本目录）
│   ├── __init__.py             ← 4 个函数签名（与主服务的契约，已提供）
│   ├── 接口规范.md              ← 本文档
│   ├── detect_vehicles.py      ← 车辆检测实现（新建）
│   ├── recognize_plate.py      ← 车牌识别实现（新建）
│   ├── detect_anomalies.py     ← 异常检测实现（新建）
│   ├── detect_violations.py    ← 违停判断实现（新建）
│   ├── weights/                ← 模型权重文件（如 yolov8n.pt 等）
│   └── ...                     ← 其他辅助代码
├── cloud_server/               ← 主服务（不修改模型代码）
│   └── pipeline/nodes/         ← 从 model_api import 函数
└── ...
```

> **注意**：目录名使用下划线 `model_api` 而非连字符 `model-api`，因为 Python 的 `import` 语句要求包名是合法的 Python 标识符。

---

## 概述

模型同学需在 `program/model_api/` 目录下实现 **4 个 Python 函数**。主服务通过 `from model_api import xxx` 直接调用。同一进程内函数调用，numpy 数组直接传递，无 HTTP、无 JPEG 编解码、无 JSON 序列化开销。

---

## 函数索引

| 序号 | 函数名 | 说明 |
|------|--------|------|
| 1 | `detect_vehicles` | 传入 BGR 帧 (numpy)，返回车辆列表 |
| 2 | `recognize_plate` | 传入车辆 ROI (numpy)，返回 (车牌号, 置信度) |
| 3 | `detect_anomalies` | 传入 BGR 帧 (numpy)，通过深度估计返回异常列表 |
| 4 | `detect_violations` | 传入车辆数据 + 禁停区配置，返回违停事件（有状态） |

## 函数 1：车辆检测

```python
def detect_vehicles(frame: np.ndarray) -> list[dict]
```

| | |
|------|------|
| **输入** | `frame` — `np.ndarray` 形状 `(H, W, 3)`，BGR，`uint8`。原始监控帧，未做预处理 |
| **输出** | `list[dict]`，每项 `{"box": [x1,y1,x2,y2], "class": "car"/"truck"/"bus"/"motorcycle", "confidence": float}` |
| **空结果** | `[]` |

- 推荐 YOLOv8n / YOLO26n，权重放 `model_api/weights/`
- 置信度阈值默认 `0.25`
- 延迟目标：< 50ms (GPU)

---

## 函数 2：车牌识别

```python
def recognize_plate(vehicle_roi: np.ndarray) -> tuple[str, float]
```

| | |
|------|------|
| **输入** | `vehicle_roi` — `np.ndarray` BGR，`uint8`。车辆 ROI 裁剪图，调用方已做预处理 |
| **输出** | `(plate_number: str, confidence: float)`。未识别到返回 `("", 0.0)` |

> 调用方使用 SORT `track_id` 缓存：同一辆车只调一次本函数，后续帧复用缓存。本函数只需专注单次识别，无需去重。

- 推荐 HyperLPR3 或 PaddleOCR
- 延迟目标：< 100ms (GPU)

## 函数 3：路面异常物体检测

```python
def detect_anomalies(frame: np.ndarray) -> list[dict]
```

### 核心要求：不使用预定义类别

最终测试时的异常物体**类型完全未知**，不能依赖类别标签匹配。必须基于 **Depth Anything V2 深度估计**实现：

1. 单帧 RGB → 像素级深度图
2. 拟合路面参考平面
3. 标记深度突变区域 → 异常候选框

| | |
|------|------|
| **输入** | `frame` — `np.ndarray` 形状 `(H, W, 3)`，BGR，`uint8` |
| **输出** | `list[dict]`，每项 `{"box": [x1,y1,x2,y2], "confidence": float, "label": "road_anomaly"}` |
| **空结果** | `[]` |

- 调用方采纳 `confidence >= 0.4` 的结果
- 模型：Depth Anything V2 ViT-Small
- 深度偏差阈值：`0.3`
- 延迟目标：< 100ms (GPU)

## 函数 4：违停判断

```python
def detect_violations(
    vehicles: list[dict],
    no_parking_zones: list[dict],
    timestamp: float,
    parking_threshold: float,
    image_width: int,
    image_height: int,
    device_id: str = "",
) -> list[dict]
```

### 输入

| 参数 | 类型 | 说明 |
|------|------|------|
| `vehicles` | `list[dict]` | 当前帧车辆，每项 `{"track_id": int, "box": [x1,y1,x2,y2], "class": str}` |
| `no_parking_zones` | `list[dict]` | 禁停区，每项 `{"name": str, "points": [[x,y],...]}`（归一化坐标 [0,1]） |
| `timestamp` | `float` | Unix 时间戳（秒） |
| `parking_threshold` | `float` | 违停判定秒数 |
| `image_width` | `int` | 原图宽度 |
| `image_height` | `int` | 原图高度 |
| `device_id` | `str` | 设备标识 |

### 输出

`list[dict]`，每项 `{"vehicle_id": int, "zone_name": str, "duration": float, "box": [x1,y1,x2,y2], "contact_point": [x, y]}`。无违停返回 `[]`。

### 状态管理（有状态）

函数内部维护 `{device_id: {track_id: {zone_name: entry_time}}}` 注册表：

1. 计算车辆底部中心归一化坐标
2. 射线法判断是否在禁停区内
3. 首次进入记录时间 → 超 `parking_threshold` 秒输出违停
4. 离开禁停区 / 离开画面 → 清除记录

- 纯计算逻辑，不涉及模型推理，延迟 < 2ms

## 坐标系约定

- **图像坐标**：原点左上角，x 右 y 下，单位像素。检测/识别函数返回的 `box` 字段均使用此坐标系
- **边界框**：`[x1, y1, x2, y2]`（左上角 + 右下角）
- **禁停区坐标**：归一化 `[0.0, 1.0]`，相对于图像宽高。违停判断在摄像头视角下进行，不需要关心俯视坐标
- **俯视世界坐标**：由主服务的 `CoordinateTransformNode` 通过单应性变换计算，模型 API 无需关心

## 错误处理

函数内部做好异常处理，不可恢复时返回空结果（`[]` 或 `("", 0.0)`），让主服务优雅降级。

## 附录：主服务坐标变换流程（供参考）

```
摄像头帧 → detect_vehicles() → 像素 box
                ↓
         SORT 跟踪 → track_id
                ↓
         CoordinateTransformNode (Homography H)
                ↓
         俯视世界坐标 (用于热力图)
                ↓
         detect_violations() ← 归一化像素坐标 (摄像头视角，不需要 H)
```

> 模型同学无需关心 Homography 标定和坐标变换，这是主服务的职责。

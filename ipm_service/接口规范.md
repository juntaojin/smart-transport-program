# 智慧交通系统 — IPM 逆透视变换服务接口规范

---

## 概述

本服务负责将**摄像头斜视视角**中的车辆像素坐标，通过**四点逆透视变换（IPM）**映射到**俯视道路平面**坐标，供前端热力图渲染。

服务挂载在现有 FastAPI 的 **8000 端口**，路由前缀 `/api/ipm`，与主服务其他接口无冲突。

### 目录结构

```
program/
├── ipm_service/                    ← 新同学的工作目录（本目录）
│   ├── __init__.py
│   ├── ipm_engine.py               ← IPM 矩阵计算 + 坐标变换
│   ├── routes.py                   ← FastAPI 路由
│   ├── config_manager.py           ← 标定配置的读写（与 config.yaml 交互）
│   └── 接口规范.md                  ← 本文档
├── cloud_server/
│   ├── main.py                     ← 需加 1 行: app.include_router(ipm_router)
│   └── config.py
├── config.yaml                     ← 标定数据存储在 ipm_service 节
└── ...
```

### 与现有标定系统的关系

| 系统 | 路由 | 用途 | 存储位置 |
|------|------|------|----------|
| 已有 Calibration | `/api/calibration` | Pipeline 内 `CoordinateTransformNode` 用（每帧变换） | `config.yaml → calibration` |
| **IPM Service（新）** | `/api/ipm` | 前端热力图渲染用（按需/定时变换） | `config.yaml → ipm_service` |

两个系统**独立运行**，配置 key 不重叠，互不影响。

## 标定约定

### 四点映射规则

采用 **4 点透视映射法**。用户在前端标定工具中，分别在摄像头画面和俯视图上标记 4 个对应点：

```
摄像头画面（斜视）              俯视图（鸟瞰）
┌──────────┐                    ┌──────────┐
│ 1──────2 │  ← 车道区域        │ 1──────2 │  ← 车道区域
│ │      │ │                    │ │      │ │
│ │      │ │                    │ │      │ │
│ 4──────3 │                    │ 4──────3 │
└──────────┘                    └──────────┘
```

**顺序约束**：必须按**顺时针**排列 —— `1:左上 → 2:右上 → 3:右下 → 4:左下`。

违反此顺序会导致 IPM 矩阵计算错误，返回的俯视坐标将不可用。

### 坐标系

| 坐标系 | 原点 | 单位 | 说明 |
|--------|------|------|------|
| 摄像头坐标 | 画面左上角 | 像素 | x 右, y 下 |
| 俯视坐标 | 俯视图左上角 | 像素 | x 右, y 下，与俯视图图片一致 |

> 俯视坐标的单位应与前端热力图底图保持一致。建议使用一张沙盘俯视照片作为底图，world_points 的坐标即该照片上的像素坐标。

### 多摄像头 + 车道隔离

同一个物理摄像头可能覆盖多条车道（如双向道路的上行/下行），每条车道需要**独立标定**。

隔离键为 `(camera_id, lane_id)`，例如：
- `(camera_01, northbound)` — 摄像头1的上行车道
- `(camera_01, southbound)` — 摄像头1的下行车道
- `(camera_02, main_lane)` — 摄像头2的主车道

前端批量请求热力图数据时，可一次传入多个 `(camera_id, lane_id)` 组合。

### 配置存储格式（config.yaml）

```yaml
ipm_service:
  camera_01:
    northbound:
      camera_points: [[100, 200], [800, 180], [820, 500], [80, 520]]
      world_points:  [[50, 100], [400, 100], [400, 300], [50, 300]]
      homography_matrix:
        - [0.51234, -0.0123, 25.678]
        - [0.0012, 0.4876, -15.234]
        - [0.00001, -0.00002, 1.0]
    southbound:
      camera_points: [[900, 200], [1200, 180], [1220, 500], [880, 520]]
      world_points:  [[450, 100], [800, 100], [800, 300], [450, 300]]
      homography_matrix: ...
  camera_02:
    main_lane: ...
```

// 失败

### 1. 计算并保存 IPM 标定

```http
POST /api/ipm/calibrate
```

**请求体**：

```json
{
  "camera_id": "camera_01",
  "lane_id": "northbound",
  "camera_points": [
    [120, 200],
    [780, 180],
    [800, 520],
    [100, 500]
  ],
  "world_points": [
    [60, 80],
    [420, 80],
    [420, 320],
    [60, 320]
  ]
}
```

**字段说明**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `camera_id` | string | 是 | 摄像头唯一标识 |
| `lane_id` | string | 是 | 车道唯一标识（同一摄像头内不重复） |
| `camera_points` | `[[float,float]]` | 是 | 摄像头画面中 4 个点的像素坐标，**顺时针：左上→右上→右下→左下** |
| `world_points` | `[[float,float]]` | 是 | 俯视图中对应的 4 个点的像素坐标，顺序与 camera_points 一致 |

**约束**：
- `camera_points` 和 `world_points` 必须各为 **恰好 4 个**点
- 点数不足 4 → 返回 `400 Bad Request`
- 点数超过 4 → 仅使用前 4 个点
- 4 个点必须大致构成四边形（不能三点共线），否则 `cv2.findHomography` 会返回错误

**成功响应**：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "camera_id": "camera_01",
    "lane_id": "northbound",
    "homography_matrix": [
      [0.5123, -0.0123, 25.678],
      [0.0012, 0.4876, -15.234],
      [1e-05, -2e-05, 1.0]
    ]
  }
}
```

**失败响应**：

```json
{"code": 400, "message": "camera_points 和 world_points 必须各有恰好 4 个点", "data": null}
```

### 2. 坐标变换

```http
POST /api/ipm/transform
```

#### 2a. 单摄单车道模式

```json
{
  "camera_id": "camera_01",
  "lane_id": "northbound",
  "vehicles": [
    [320, 350],
    [600, 380],
    [150, 420]
  ]
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `camera_id` | string | 是 | |
| `lane_id` | string | 是 | |
| `vehicles` | `[[float,float]]` | 是 | 车辆在摄像头画面中的像素坐标列表，每个点为 `[x, y]`。**空数组 `[]` 合法**，返回空结果 |

**响应**：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "transformed": [
      [165.3, 210.7],
      [295.1, 215.2],
      [80.5, 230.0]
    ]
  }
}
```

`transformed[i]` 与 `vehicles[i]` 一一对应。

**未标定**（指定的 `(camera_id, lane_id)` 未找到）：

```json
{"code": 404, "message": "标定数据不存在: camera_01 / northbound", "data": null}
```

#### 2b. 批量模式（热力图一次请求多摄多车道）

```json
{
  "requests": [
    {
      "camera_id": "camera_01",
      "lane_id": "northbound",
      "vehicles": [[320, 350], [600, 380]]
    },
    {
      "camera_id": "camera_01",
      "lane_id": "southbound",
      "vehicles": [[800, 400], [500, 450]]
    },
    {
      "camera_id": "camera_02",
      "lane_id": "main_lane",
      "vehicles": []
    }
  ]
}
```

**响应**：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "results": [
      {
        "camera_id": "camera_01",
        "lane_id": "northbound",
        "transformed": [[165.3, 210.7], [295.1, 215.2]]
      },
      {
        "camera_id": "camera_01",
        "lane_id": "southbound",
        "transformed": [[380.5, 215.0], [210.8, 230.5]]
      },
      {
        "camera_id": "camera_02",
        "lane_id": "main_lane",
        "transformed": []
      }
    ]
  }
}
```

**部分失败**：如果批量请求中某个 `(camera_id, lane_id)` 未标定，其 `transformed` 返回 `null` 而非空数组，其他正常返回：

```json
{
  "camera_id": "camera_02",
  "lane_id": "unknown_lane",
  "transformed": null
}
```

### 请求模式自动识别

服务根据请求体中是否存在 `requests` 字段自动判断模式：
- 有 `requests` → 批量模式
- 无 `requests` → 单摄单车道模式

## 实现要求

### IPM 算法

使用 OpenCV `cv2.findHomography`（RANSAC）计算 3×3 单应性矩阵 H，然后用 `cv2.perspectiveTransform` 做坐标映射。

```python
import cv2
import numpy as np

def compute_ipm(camera_points, world_points):
    src = np.array(camera_points, dtype=np.float32).reshape(-1, 1, 2)
    dst = np.array(world_points, dtype=np.float32).reshape(-1, 1, 2)
    H, _ = cv2.findHomography(src, dst, cv2.RANSAC, 5.0)
    return H

def transform_points(points, H):
    pts = np.array(points, dtype=np.float32).reshape(-1, 1, 2)
    result = cv2.perspectiveTransform(pts, H)
    return result.reshape(-1, 2).tolist()
```

### 服务挂载

在 `ipm_service/routes.py` 中创建 `APIRouter(prefix="/api/ipm")`，然后在 `cloud_server/main.py` 中加一行：

```python
from ipm_service.routes import router as ipm_router
app.include_router(ipm_router)
```

## 前端交互规范

### 标定流程

1. 前端展示双栏：左 = 摄像头实时画面，右 = 俯视图底图
2. 用户在两栏各点 4 个点（顺时针：左上→右上→右下→左下）
3. 点击"计算标定" → `POST /api/ipm/calibrate`
4. 标定成功后，车道配置显示在列表中

### 热力图刷新（模式 C：定时刷新）

1. 前端展示热力图 + "自动刷新"开关
2. 开启后每 **5 秒**（默认）调用 `POST /api/ipm/transform`（批量模式）
3. 车辆坐标来源：每 5 秒从最新一帧的 `world_coords` 中取，或直接从 `POST /api/ipm/transform` 传入
4. 返回的俯视坐标渲染到热力图图层上

### 车辆坐标来源

前端从 WebSocket 推送的 JSON 中读取每辆车的 `box`（像素坐标），取底部中心点 `( (box[0]+box[2])/2, box[3] )`，传入 `/api/ipm/transform` 的 `vehicles` 字段。

## 常见问题

### Q: camera_points 顺序错了会怎样？
坐标映射结果会错误（旋转或镜像）。前端标定工具应引导用户按顺时针点击。

### Q: 同一个摄像头可以标定多条车道吗？
可以，用不同的 `lane_id` 区分。每个 `(camera_id, lane_id)` 独立存储。

### Q: 标定后俯视图底图换了怎么办？
需要重新标定，或调 `DELETE` 删除旧的，再 `POST` 新的。

### Q: 批量模式能传多少个请求？
无硬性限制。建议前端控制单次不超过 10 个 `(camera_id, lane_id)` 组合。

### Q: 车辆坐标在哪取？
- **方案 A（推荐）**：前端从 WebSocket 推送数据里取每辆车 `box`，算底部中心点，传入本接口
- **方案 B**：在 `ipm_service/routes.py` 中读取 `cloud_server.api.ws_routes` 的 `plate_db` 或其他共享状态（需处理线程安全）

建议方案 A，本接口保持无状态。
